# {{TOPIC}} — 지도

> **작성 주체: 🤖 AI** (내가 쓰는 게 아니다)
> **언제:** 학습 시작 첫날, 30분 이내
> **목적:** 뭘 파고들지 고르기 위한 목차. 이해하기 위한 문서가 아니다.
>
> ⚠️ **이 파일의 유일한 실패 조건은 "너무 자세해지는 것"이다.**
> 여기서 상세 설명까지 받으면 다 아는 것 같아서 `01`~`05`를 안 하게 된다.
> 그러면 이 프로젝트를 할 이유가 없어진다. **두 문장 이내로 끊는다.**

## 쓰는 방법

아래 프롬프트를 그대로 AI에게 던지고, 답변을 이 파일에 붙여넣는다.

```
{{TOPIC}}의 전체 흐름을 지도처럼만 그려줘.
- 단계 이름과 순서
- 각 단계의 핵심 용어와 용어끼리의 관계
- 이 주제의 경계 (어디까지가 이 주제이고 어디부터가 아닌지)

각 항목은 두 문장 이내로. 자세한 설명은 하지 마.
내가 나중에 뭘 파고들지 고르는 용도야.
```

붙여넣은 뒤 **바로 `01-QUESTIONS.md`로 넘어간다.** 여기서 더 물어보지 않는다.

## 어느 정도가 "얇은" 것인가

**이 파일 전체가 A4 한 장을 넘으면 실패다.** 목차는 목차 분량이어야 한다.

| | 좋은 지도 | 나쁜 지도 |
|---|---|---|
| 예 | "서버 상태 — 원격이 진실인 데이터. 낡을 수 있어서 재검증이 필요하다." | "서버 상태는 클라이언트 상태와 달리 비동기적이며, 캐싱 전략에 따라... (10줄 계속)" |
| 판별법 | 읽어도 **설명은 못 하겠고 뭘 모르는지만 보인다** | 읽고 나면 **다 안 것 같다** |

**"다 안 것 같다"는 느낌이 들면 지도가 너무 두꺼운 것이다.**
그 상태로는 `01`에서 질문이 안 나오고, 결국 나머지 단계를 건너뛰게 된다.

### AI 답변이 너무 길게 오면

그대로 붙여넣지 말고 다시 시킨다.

```
너무 자세해. 각 항목을 한 문장으로 줄여줘.
나는 지금 이해하려는 게 아니라 목차만 필요해.
```
