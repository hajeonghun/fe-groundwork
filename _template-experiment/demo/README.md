# {{TOPIC}} — 데모

## 실행

```bash
# 파일 프로토콜로 열면 일부 API가 막히므로 서버로 띄운다
python3 -m http.server 8000

# http://localhost:8000/bad.html
# http://localhost:8000/good.html
```

`file://`로 열어도 되는 실험이면 그냥 더블클릭해도 된다.
다만 **네트워크·캐시·Worker·모듈**이 관련되면 반드시 서버로 띄운다.

---

## 역할 분담

| 파일 | 주체 | 설명 |
|------|------|------|
| `bad.html` | 🤖 AI | 문제가 있는 버전. 만드는 데 배울 게 없으니 맡긴다 |
| `good.html` | 🧑 나 | 개선 버전. **내가 고치는 게 학습이다.** 막히면 힌트만 받는다 |

### AI에게 bad 버전을 시킬 때

```
{{TOPIC}}의 [구체적 문제]를 눈으로 확인할 수 있는 최소 재현 페이지를 만들어줘.
- 의존성 없이 HTML 파일 하나로
- 문제가 계측 도구에서 뚜렷하게 보이도록
- 무엇을 어떤 도구로 봐야 하는지도 알려줘
- 개선 방법은 알려주지 마. 내가 직접 고칠 거야
```

**마지막 줄이 중요하다.** 개선 방법까지 받으면 `good.html`을 만드는 의미가 없어진다.

---

## 측정 전 반드시

1. **결과를 먼저 예측하고 `03-MEASUREMENTS.md`에 적는다.** 실행 후에 적으면 사후 합리화가 된다.
2. **다른 탭·확장 프로그램을 끈다.** 특히 성능 측정 시 확장이 결과를 크게 흔든다.
3. **최소 3회 측정한다.** 1회 측정은 신뢰할 수 없다.
4. **CPU 스로틀링을 켠다.** 개발 머신은 사용자 기기보다 훨씬 빠르다. 4~6배가 현실적이다.
